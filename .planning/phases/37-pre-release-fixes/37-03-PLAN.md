<objective>
Resolve the orphaned helper function situation identified in the v2.0.4 audit.

Current state:
- `main.py` line 160 uses a raw `get_runtime_mode() != 'agent'` guard for the banner
- `should_check_for_updates()` in `runtime.py` (lines 147-176) does exactly this check and also prints an informational message "Updates managed via container builds" for users running inside a container — but it is never called in production code
- `check_for_updates()` in `version_check.py` (lines 318-324) is a thin wrapper around `VersionChecker().start_background_check()` with no callers anywhere in production code

Chosen approach (per BACKLOG.md): Wire `should_check_for_updates()` into `main.py` in place of the raw guard. Delete `check_for_updates()` (no callers, no tests). Leave `update_version_config()` alone — it is actively used by `update.py` and `banner.py`.

Purpose: Eliminate dead public API surface; give agent-mode users an informational "Updates managed via container builds" message rather than silent suppression.
Output: `main.py` calls `should_check_for_updates()`; `check_for_updates()` removed from `version_check.py`.
</objective>
