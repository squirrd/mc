### Phase 36: OCM Token Background Monitor

**Goal:** Add a host-side daemon thread that monitors OCM refresh token expiry every 30 minutes and notifies the user + triggers re-login when expiry is within 60 minutes.
**Requirements:** OCM-01, OCM-02, OCM-03, OCM-04, OCM-05
**Plans:** 2 plans

Plans:
- [x] 36-01-PLAN.md — OCM monitor core module (ocm_monitor.py + unit tests)
- [x] 36-02-PLAN.md — Wire start_background_monitor() into main.py

**Details:**
Daemon thread started on every host-mode `mc` invocation. JWT decode checks `exp` claim; warns and triggers `ocm login --use-auth-code --url=prd` when <60 min remaining. Informational message when ocm.json absent.

## Milestone Summary

**Key Decisions:**
- CASE_NUMBER passed to `podman exec` via implicit env-inheritance (set at container creation time) rather than explicit `--env` flag — works today, noted as tech debt
- OCM monitor uses daemon thread (same pattern as version_check.py) — consistent threading semantics
- Case data written to /case/ (agent workspace) not /tmp — persistent across exec sessions

**Issues Resolved:**
- StateDatabase path bug (BPL-04): _get_state_db() used relative path, silently broke backplane login when called from inside container exec
- Banner orphaned helpers: check_for_updates() / update_version_config() were dead public API — deleted
- Integration test stale APIs: image= argument removed from ContainerManager.create(); proxy mock added

**Issues Deferred:**
- OCM silent refresh without browser interaction (OCM-F01/F02) — requires token endpoint investigation
- CASE_NUMBER explicit env passthrough in build_exec_command() — low-severity, implicit inheritance works

**Technical Debt Incurred:**
- CASE_NUMBER implicit env passthrough to podman exec — works but implicit dependency
